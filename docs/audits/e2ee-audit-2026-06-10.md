## Executive summary

**Since June 5 the team closed the entire plaintext-leak cluster and about a third of the UX list, but the headline guarantees still have holes on both audit axes:**

1. **Parity axis:** sources/citations are still entirely absent from encrypted replies and trace steps (E2EE-9/14 remain open — the single biggest visible parity gap). Encrypted threads ship without the anchor message, so Ariadne literally cannot see what a new thread is about (FP-2). `@ariadne` mentions in quiet encrypted scratchpads are silently dead (FP-3).
2. **Seamlessness axis:** the "Ariadne looks dead" cluster (E2EE-8/12/13/25) is untouched — parked turns are invisible and DLQ exhaustion is silent. The decrypt-masking cluster (UX-2, 13, 22, 24, 25) is untouched. **Locked encrypted threads bypass the full-page gate entirely** — a wall of locked placeholders with no unlock affordance and a live composer that errors on send (UXN-1). And a new integration bug hollows out three already-merged PRs: **`VirtualStream` strips the sealed-name fields, so enclave-generated auto-titles are stored but never rendered — encrypted scratchpads still read "New scratchpad" everywhere** (UXN-A below).
3. **Isolation axis (the "avoid the system" guarantee):** GAM exclusion holds at every server sink, plaintext→E2E conversion is structurally impossible, the enclave emits no telemetry, and OpenRouter is pinned to zero-retention. Four real cracks: the enclave's shared web tools **log plaintext-derived search queries and URLs** (FP-1); **slash commands bypass every E2E gate** — plaintext args persist on E2E streams and can invoke external bots (ISO-1); **dictation routes E2E-destined text through external STT and a Langfuse-instrumented polish call** (ISO-2); and **plaintext still sits at rest in IndexedDB** via optimistic events, pending sends (which survive sign-out), and stashed drafts (ISO-3 — the lock model's "memory only" claim is still false despite the E2EE-4 fix).
4. **Unfixed criticals from June 5:** passphrase rotation still strands every existing stream (E2EE-6, latent — no UI calls it) and an old-generation parked turn still parks forever (E2EE-7).

### UXN-A (high) — `VirtualStream` strips the sealed-name fields; decrypted/auto-generated titles never render anywhere

The single most consequential re-audit discovery. `useDecryptedStreamName` is the only sealed-name renderer and its sole call site is the stream header (`stream.tsx:113`), which receives a `VirtualStream` whose constructed literal drops `sealedNameCiphertext`/`sealedNameEnvelope` (`use-stream-or-draft.ts:448-464`; interface at `:90-115`). The hook's source key is therefore always null and it always returns null. The sidebar reads plaintext `displayName` only (`scratchpad-item.tsx:63-64`). This silently hollows out PR #794 (UX-5: titles generated, stored, never shown), keeps UX-20 (name drift) open, and reduces PR #787 (UX-35 rename pre-fill) to a no-op for the auto-title case.

**Fix:** pass `sealedNameCiphertext`/`sealedNameEnvelope` through the `VirtualStream` literal and adopt `useDecryptedStreamName` in the sidebar item — one small change realizes the value of three already-merged PRs.

## New findings — feature parity (FP)

The deliberate exceptions (per product intent): no GAM memory generation, no workspace tools (memory recall, reading other streams). Everything else is held to the parity bar.

### FP-1 (high) — Enclave logs plaintext-derived web queries, URLs, and research phase text

The enclave reuses the shared web tools, whose failure paths log user-derived content at warn/error — which fire at the enclave's default `info` level (`packages/agent-runtime/src/logger.ts:13`): `read-url-tool.ts:216,227,234,296,302` log `input.url`; `web-search-tool.ts:98,130,139` log the search `query` and Tavily's raw error text; `general-researcher.ts:108` logs substep text ("Searching the web: <query>"). Search queries and URLs are derived from the decrypted prompt — exactly the "what was researched" class the sealed-sources design says must never leave in clear. Contradicts `e2e-encrypted-scratchpads.md:22` ("never logs payloads"); the enclave scrubs its _own_ errors (`session-runner.ts:72-78`) while the tool layer leaks below it.

**Fix:** inject a content-scrubbing logger (or `redactContent` flag) into the shared web tools when built for the enclave; audit every `logger.*` reachable from the enclave-runtime barrel.

### FP-2 (high) — Encrypted threads: Ariadne never sees the anchor message

Plaintext `buildThreadContext` prepends the parent message the thread was opened on — its own comment says "the reply chain is unintelligible without it" (`agents/context-builder.ts:341-371`). The enclave dispatch ships only `findSurrounding` over the thread stream (`enclave-invoke-worker.ts:110`; `request-builder.ts:89-95`), so the first turn in a new encrypted thread has empty history and "what do you think about this?" has zero referent. The system prompt is also built against the root scratchpad with no thread framing (`enclave-invoke-worker.ts:111-113,129`).

**Fix:** include the anchor message's ciphertext (sealed under the same root SSK) as the first history item in the assignment.

### FP-3 (medium) — `@ariadne` mention in a quiet encrypted scratchpad is silently dead

Plaintext mentions invoke Ariadne regardless of companion mode (`mention-invoke-outbox-handler.ts:138-163`). For E2E the mention handler short-circuits (mentions ride in ciphertext, `:113-116`) and the enclave dispatch fires only with companion mode ON (`enclave-dispatch-handler.ts:104-125`). Quiet encrypted scratchpads are a supported state, and the composer's @-mention suggestion is not e2e-gated — the user types `@ariadne`, it renders as a mention, nothing ever happens.

**Fix:** let the client set a clear, non-secret "invoke companion" flag on the sealed send (the client sees the plaintext mention), honored by dispatch even in quiet mode — or suppress persona mentions in the E2E composer with an explanation.

### FP-4 (medium) — Enclave turns invisible to AI usage/cost accounting; data reported then discarded

The enclave sums non-secret token usage (`enclave-ai.ts:40-41`) and ships it on `/complete`; the schema parses it (`session-handlers.ts:60-64`) but the handler reads only `messageIds` (`:448`) — `usage` and `model` are dropped. Plaintext turns are cost-attributed via `ai_usage_records`. Token counts aren't secret; nothing in the trust model forbids recording them.

**Fix:** write an `ai_usage_records` row in the complete handler from `usage` + `model`.

### FP-5 (medium) — History fidelity: bare role/content vs timestamps, authorship, msg-ids, reactions, quote expansion, rolling summary

Plaintext history is annotated (`[msg:… author:…] (14:30)`, date boundaries, attachment captions, reactions — `companion/prompt/message-format.ts:7-27`), quote/shares expanded (`companion/context.ts:177-280`), with a rolling summary for older context. Enclave history is `{ role, content }` only (`run-turn.ts:137-149`) over a 30-message window — "what did I write yesterday?" is unanswerable, and sealed replies can never carry quote pointers. Timestamps/authors are clear metadata the backend already has.

**Fix:** ship per-message `createdAt`/author metadata on the assignment and format with the shared temporal formatter in-enclave; consider an in-enclave rolling summary.

### FP-6 (medium) — Office documents (xlsx/docx) readable by plaintext Ariadne are dead weight in the enclave

Server extraction pipelines (excel/word/pdf/image-caption) feed plaintext context; the enclave handles images, PDFs, and UTF-8 text but degrades anything else to "binary format I can't read" (`run-turn.ts:322-336`) while the backend still ships the bytes at full cost. Server extraction is off by design; in-enclave parsing is not forbidden.

**Fix:** bundle a minimal xlsx/docx extractor into the enclave, or document the boundary (the feature doc currently claims broad "Ariadne reads them too").

### FP-7 (medium) — GitHub/Linear tools missing from encrypted Ariadne beyond the stated exceptions

Plaintext scratchpad Ariadne gets 15 GitHub + 4 Linear read tools, also inside `general_research` (`built-in-agents.ts:73-91`; `general-researcher/config.ts:49-77`). The enclave is web-only. These are third-party reads, not workspace reads; the enclave could call them directly with short-lived tokens minted into the assignment (same egress pattern as Tavily).

**Fix:** ship scoped tokens on the assignment and run the same tool defs in-enclave, or add GitHub/Linear to the documented intentional-off list.

### FP-8 (low) — `web_search` recency grounding built but unwired

`run-turn.ts:102-106` and `tools.ts:72` accept `currentTime`/`timezone`, but `session-runner.ts:65` constructs `tools: { tavilyApiKey }` only — never populated. "Latest/news" searches lose date anchoring.

**Fix:** pass `currentTime` (and owner timezone from the assignment) through `session-runner.ts`.

### FP-9 (low) — Encrypted Ariadne cannot react to messages

`react_to_message` is in the plaintext tool list; absent from the enclave's. Reactions are clear metadata (users can react on E2E messages; emoji stats handler merely skips).

**Fix:** add a clear-metadata `react` session callback + tool, or list as intentional-off.

### FP-10 (low) — Inline "Ariadne is working…" card always reports 0 messages for enclave turns

`emitInlineProgress` hardcodes `messageCount: 0` (`session-handlers.ts:147`) even after interim replies; plaintext increments.

**Fix:** count `message_sent` steps in the same handler.

### FP-11 (low) — Enclave CONTEXT trace step omits the "Recent context" message list

Plaintext `context_received` carries trigger + up to 4 preceding messages with a dedicated renderer section; the enclave seals exactly one message (`trace-observer.ts:184-209`) despite having decrypted history in hand.

**Fix:** include the last few history messages (capped, mirroring plaintext) in the sealed context payload.

### FP-12 (low) — Quiet encrypted scratchpads never auto-title; titled ones only after Ariadne's first reply

Plaintext naming fires on any message in an unnamed scratchpad. Enclave titling requires companion ON + successful reply (`enclave-invoke-worker.ts:170`; `run-turn.ts:261-276`). The naming handler's comment "The client picks a name locally instead" (`naming-outbox-handler.ts:120-121`) describes code that doesn't exist.

**Fix:** client-side title generation + seal on first send for quiet E2E scratchpads, or correct the comment/doc.

## New findings — isolation (ISO)

The "avoid the system" guarantee: no GAM memory generation from encrypted content, no server-side or telemetry surface sees plaintext.

### ISO-1 (medium) — Slash-command dispatch has no E2E guard; plaintext args persist on E2E streams and bot-runtime invocations bypass the E2EE-11 gate

`commands/handlers.ts:33-122` — `dispatch` accepts any `streamId` with no `isE2eStream` check, and the slash menu is offered in E2E composers (commands are workspace-global; `message-composer.tsx` has no e2e gating). Command `args` — user-typed text, e.g. `/remind <sensitive text>` — are persisted **plaintext** into `stream_events` on the E2E stream and echoed through the outbox (`commands/events.ts:67-87`). Worse, the `BOT_RUNTIME` kind calls `botRuntimeService.createInvocationInTransaction` directly (`handlers.ts:102-119`), skipping the message-driven E2E short-circuit that E2EE-11 added — an external bot can be invoked from an E2E stream with plaintext args.

**Fix:** `isE2eStream` check in `dispatch` — reject (mirroring `E2E_STREAM_SCHEDULING_UNSUPPORTED`) or allow only a content-free allowlist; at minimum block the bot-runtime kind. Gate the slash menu in E2E composers.

### ISO-2 (medium) — Dictation ignores E2E: transcript of E2E-destined content transits backend, external STT, and a telemetry-instrumented LLM

Voice sessions are not stream-scoped (`voice-transcription/service.ts:30-53`) so the server can't distinguish an E2E target, and the mic button is not hidden in E2E composers. The polish LLM call includes `telemetry` (`voice-transcription/polish.ts:55`) — dictated text destined for an encrypted scratchpad is likely captured in Langfuse prompt/response traces.

**Fix:** disable dictation in E2E composers (or warn explicitly), and/or exclude polish bodies from telemetry.

### ISO-3 (high) — E2E plaintext at rest in IndexedDB: optimistic events, pending sends, and stashed drafts survive lock — pending sends even survive sign-out

The lock model's claim that "the in-memory cache is the only surface holding plaintext" (`e2e-session-store.ts:909-911`) is still false even after the E2EE-4 fix (which covered composer drafts via `useDraftMessage`):

- The optimistic event written to `db.events` carries plaintext `contentMarkdown`/`contentJson`, and `db.pendingMessages` stores plaintext alongside the ciphertext (`use-queue-draft-message.ts:66-84,128-152`). Both are deleted only on server echo (`stream-sync.ts:532-547`) — offline or permanently-failed sends leave plaintext in IDB indefinitely.
- `clearAllCachedData` deliberately **keeps `pendingMessages` across sign-out** (`db/database.ts:1058`), so queued E2E plaintext survives logout.
- `stashedDrafts` (`stores/draft-store.ts`) stores plaintext `contentJson` with zero e2e handling.
- `lock()` (`e2e-session-store.ts:907-931`) purges only the in-memory caches — none of these tables.

**Fix:** for E2E sends store only ciphertext in the queue and seed the decrypt cache in memory for the echo; purge E2E-stream pending/optimistic/stashed rows on `lock()` and sign-out.

### ISO-4 (low) — `revokeKeyForUser` doesn't clear decrypted-content caches

`e2e-session-store.ts:882-898` deletes key material but, unlike `lock()` and `resetE2eSessionStoreCache`, never calls `clearDecryptCache()`/`clearStreamKeyCache()`/`clearAttachmentRefCache()` — decrypted plaintext remains renderable in memory until reload. **Fix:** add the three clears.

### ISO-5 (low) — Attachment processing handler relies on structural guard, not an explicit `e2eOnly` check

`attachments/uploaded-outbox-handler.ts:100-168` routes purely on mime/filename; isolation holds because `AttachmentService.create()` never emits `attachment:uploaded` for E2E rows (`attachments/service.ts:113-135`, placeholders forced twice). Sound today, but any future path emitting the event for an `e2e_only` row would route ciphertext into `TEXT_PROCESS`. **Fix:** cheap `e2eOnly` short-circuit in the handler to make it self-defending.

### ISO-6 — Ciphertext-in-logs: none found

No logger call in the E2E path includes ciphertext, envelopes, or derived content (`session-handlers.ts:532`, `enclave-dispatch-handler.ts:133`, `enclave-invoke-worker.ts:246-309`, `forwarder.ts`). (The plaintext-derived _tool-layer_ logging in the enclave is FP-1.)

## New findings — UX seamlessness (UXN)

See UXN-A above (sealed names never render — the highest-leverage fix in this report). Further journey findings:

### UXN-1 (high) — Locked encrypted threads bypass the gate entirely

The full-page gate only fires for `type === SCRATCHPAD && e2eEnabled` (`stream.tsx:147,485`), so a thread under an encrypted root — via thread page, side panel, or deep link — renders a wall of "🔒 Locked — unlock to view" rows with **no unlock affordance anywhere** (the header pill is also scratchpad-gated, `stream.tsx:402`; `thread/stream-panel.tsx` has zero gate/unlock code). The composer is live: the user can type a reply and only on send hits a thrown "Unlock encrypted scratchpads before sending" (`seal-send.ts:42-43`). This is exactly the locked-placeholder-wall the gate was built to prevent.

**Fix:** gate on `stream.e2eEnabled` for any stream type (page + panel); at minimum mount the unlock affordance and disable the composer when locked.

### UXN-2 (high) — "Save as draft" (stash) writes E2E plaintext to IndexedDB

The auto-draft path is memory-only for E2E (E2EE-4 fix), but the explicit stash path has no gate: `StashedDraftsPicker` renders unconditionally in E2E composers (`stream-panel.tsx:184-205`) and `stashDraft` persists raw `contentJson` via `db.stashedDrafts.add` (`use-stashed-drafts.ts:69`; `use-stash-composer.ts:44-55`). One click defeats the no-plaintext-at-rest guarantee, and the stash is readable (via the /drafts explorer and `?stash=` deep link) even while locked. (Same residue class as ISO-3.)

**Fix:** hide the stash trigger when `e2eEnabled`, or seal stash rows under the SSK.

### UXN-3 (high) — Voice dictation in an E2E composer streams audio to the server

The mic button is always available (`message-composer.tsx:661-663`); `use-voice-dictation.ts:545` opens a server transcription session and the polish pass sends text to an LLM — no `e2eEnabled` gate or disclosure. Message content transits the server in the clear (audio + transcript) before being "sealed". This is the UX face of ISO-2 (which adds: the polish call is Langfuse-instrumented).

**Fix:** gate the mic on `e2eEnabled`, or show an explicit "dictation is processed server-side" disclosure.

### UXN-4 (high) — No edit on encrypted messages, with no explanation

Edit is silently hidden (`message-actions.ts:49-53,232`) and the backend refuses (`E2E_STREAM_EDIT_UNSUPPORTED`). Correct for safety (E2EE-1), but the felt cost is real: a typo means delete-and-resend, and the affordance vanishing is unexplained. **Fix:** a sealed-edit path (re-seal ciphertext + envelope, version the ciphertext); interim, a disabled Edit entry with a tooltip.

### UXN-5 (medium) — Share fast paths produce empty/broken shares of sealed messages

The modal path handles E2E correctly when unlocked (decrypt-confirm, `share-message-modal.tsx:156-172`), but (a) the "share to root/parent" fast-path menu entries call `queueShareHandoff` with no `sourcePlaintext` and no confirm (`message-event.tsx:1090-1111`) — a pointer share of a sealed message, which the shared-message renderer cannot decrypt, so the quote card renders the zero-width placeholder, i.e. blank; (b) when the row is locked or decrypt failed, `e2eDecryptedMarkdown` is undefined so the modal silently takes the broken pointer path too.

**Fix:** route fast paths through the decrypt-confirm flow; disable share while not decrypted.

### UXN-6 (medium) — "Discuss with Ariadne" on an encrypted message hands Ariadne nothing

Offered ungated on E2E messages (`message-actions.ts:320`); it creates a plaintext companion scratchpad with the encrypted stream as context (`use-discuss-with-ariadne.ts:30-45`), but the context-bag summarizer has no E2E handling (`agents/context-bag/summarizer.ts`) and would summarize zero-width placeholders. The user gets a discussion where the AI silently knows nothing about the message they clicked.

**Fix:** hide the entry for E2E sources, or pass client-decrypted content explicitly behind a confirm.

### UXN-7 (medium) — Thread reply snippet in the timeline renders blank for encrypted threads

`ThreadCard` pipes `summary.latestReply.contentMarkdown` straight from the wire (`thread-card.tsx:108`) — for sealed messages the zero-width placeholder, so the card shows "Alice: " followed by nothing, even when unlocked. Sibling surfaces already map the placeholder to "Encrypted message" (`saved-item.tsx:203`, `stream-item.tsx:169`).

**Fix:** same label mapping at minimum; ideally decrypt the snippet client-side when unlocked.

### UXN-8 (medium) — E2E drafts silently evaporate on reload

Deliberate consequence of the E2EE-4 fix: encrypted-stream drafts are memory-only, so a half-written message is gone after reload/navigation with no warning — where plaintext drafts survive. **Fix:** persist drafts sealed under the SSK, or warn on navigation with a non-empty composer.

### UXN-9 (medium) — Saved items never decrypt and offer no unlock

`saved-item.tsx:199-204` renders a permanent static "Encrypted message" label — no client-side decrypt when unlocked (ciphertext isn't shipped to the surface), no unlock affordance when locked. The saved list is a primary recall surface; a static label makes saving encrypted messages near-useless.

**Fix:** ship ciphertext + envelope in the saved view and decrypt client-side when unlocked.

### UXN-10 (low) — /giphy search queries from an encrypted composer transit the server

The picker is offered in E2E composers and search/trending proxy through the backend (`api/giphy.ts:14-33`), so the server observes picker queries typed inside an encrypted room; the chosen GIF loads from Giphy's CDN on every render. The embed itself rides sealed in `contentJson` (verified) and locked rows can't leak refs. **Fix:** disclosure, or accept and document.

### UXN-11 (low) — Content actions on locked rows operate on the placeholder string

Swipe-quote quotes the literal "🔒 Locked — unlock to view" into the composer (`message-event.tsx:872-884`); copy-as-markdown/plain copy it too (`message-actions.ts:347,363`). **Fix:** suppress content-derived actions unless `decrypted.status === "decrypted"`.

### UXN-12 (low) — Trace-step locked notice is text-only

"Unlock this scratchpad to view this step" with no unlock button (`trace-step.tsx:124-131`), unlike the gate/pill/quick-switcher which all wire `openUnlock()`.

### UXN-13 (low) — Unlock error copy jargon

"That passphrase didn't unlock the bundle." (`passphrase-unlock-modal.tsx:98`) — "bundle" is implementation vocabulary; offline with no cached key the store surfaces raw "No wrapped key available to unlock" (`e2e-session-store.ts:595`).

### Verified seamless (positive confirmations)

- Thread reply sealing shares `sealOutgoingMessage` with live send, optimistic echo incl. attachments, heals stale actor wraps (`use-queue-draft-message.ts:86-122`); draft threads inherit `e2eEnabled` (`stream-panel.tsx:167-176`).
- In-stream search decrypts client-side, warming the shared cache (`use-stream-search.ts:183-202`).
- Share modal (unlocked): explicit "Share & decrypt" confirm with clear copy.
- Copy-link-to-stream is ID-only, identical for encrypted streams (`lib/stream-links.ts:9-25`).
- PIN lockout has attempts-left messaging + passphrase fallback; biometric cancel has inline error + fallback; offline unlock resumes from the IDB bundle (`e2e-session-store.ts:406,687-712`; `biometric-unlock-modal.tsx:54-79`).
- Quick switcher and sidebar both carry unlock affordances; the gate shows a quiet spinner during hydration instead of flashing.
- Move-messages is same-stream-only, so no cross-encryption-boundary move exists; the INV-E1 sink rejects mixed payloads.
- `DecryptingPlaceholder` keeps non-zero height for virtualizer measurement under the new engine.

**Unchecked (flagged):** runtime scroll-anchor behavior on bulk decrypt under virtua (#816) — static read only; drag-to-label (no name/e2e dependencies found, should be identical); mark-unread sidebar path; revoked-key device-state copy.
