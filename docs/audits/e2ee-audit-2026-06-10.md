# E2EE Scratchpads Audit — June 10, 2026

- **Date:** 2026-06-10
- **Code state:** `main` @ `6266efb` (branch `claude/e2e-encryption-audit-aia9u2`).
- **Predecessor:** [`e2ee-enclave-audit-2026-06.md`](e2ee-enclave-audit-2026-06.md) (June 5, findings `E2EE-1..26b`, `UX-2..39`). This audit (a) re-verifies every prior finding against HEAD after the ~40 commits that landed since, and (b) adds fresh findings on the two product axes: **UX seamlessness** ("you should not notice you're using encryption other than us showing it") and **feature parity** for Ariadne in encrypted scratchpads ("a ghost chat — research, sources, traces near-identical to normal; GAM memory generation deliberately off").
- **Method:** 7 audit agents — 2 prior-finding re-verifiers (Part I / Part II), 1 fresh feature-parity finder (enclave vs in-process side-by-side), 1 fresh UX-journey finder (focused on surfaces changed since June 5: threads, auto-title, virtua timeline, Giphy, share), 1 isolation/GAM-exclusion sweeper, plus verification passes on new high findings.

New findings are referenced as `FP-<n>` (feature parity), `UXN-<n>` (UX, new), `ISO-<n>` (isolation).

## Executive summary

**Since June 5 the team closed the entire plaintext-leak cluster and about a third of the UX list, but the headline guarantees still have holes on both audit axes:**

1. **Parity axis:** sources/citations are still entirely absent from encrypted replies and trace steps (E2EE-9/14 remain open — the single biggest visible parity gap). Encrypted threads ship without the anchor message, so Ariadne literally cannot see what a new thread is about (FP-2). `@ariadne` mentions in quiet encrypted scratchpads are silently dead (FP-3).
2. **Seamlessness axis:** the "Ariadne looks dead" cluster (E2EE-8/12/13/25) is untouched — parked turns are invisible and DLQ exhaustion is silent. The decrypt-masking cluster (UX-2, 13, 22, 24, 25) is untouched. And a new integration bug hollows out three already-merged PRs: **`VirtualStream` strips the sealed-name fields, so enclave-generated auto-titles are stored but never rendered — encrypted scratchpads still read "New scratchpad" everywhere** (UXN-A below).
3. **Isolation axis (the "avoid the system" guarantee):** GAM exclusion holds at every server sink, the enclave emits no telemetry, and OpenRouter is pinned to zero-retention. The one real crack: the enclave's shared web tools **log plaintext-derived search queries and URLs** at warn/error level (FP-1), contradicting the documented "never logs payloads" guarantee.
4. **Unfixed criticals from June 5:** passphrase rotation still strands every existing stream (E2EE-6, latent — no UI calls it) and an old-generation parked turn still parks forever (E2EE-7).

### UXN-A (high) — `VirtualStream` strips the sealed-name fields; decrypted/auto-generated titles never render anywhere

The single most consequential re-audit discovery. `useDecryptedStreamName` is the only sealed-name renderer and its sole call site is the stream header (`stream.tsx:113`), which receives a `VirtualStream` whose constructed literal drops `sealedNameCiphertext`/`sealedNameEnvelope` (`use-stream-or-draft.ts:448-464`; interface at `:90-115`). The hook's source key is therefore always null and it always returns null. The sidebar reads plaintext `displayName` only (`scratchpad-item.tsx:63-64`). This silently hollows out PR #794 (UX-5: titles generated, stored, never shown), keeps UX-20 (name drift) open, and reduces PR #787 (UX-35 rename pre-fill) to a no-op for the auto-title case.

**Fix:** pass `sealedNameCiphertext`/`sealedNameEnvelope` through the `VirtualStream` literal and adopt `useDecryptedStreamName` in the sidebar item — one small change realizes the value of three already-merged PRs.

## New findings — feature parity (FP)

The deliberate exceptions (per product intent): no GAM memory generation, no workspace tools (memory recall, reading other streams). Everything else is held to the parity bar.

### FP-1 (high) — Enclave logs plaintext-derived web queries, URLs, and research phase text

The enclave reuses the shared web tools, whose failure paths log user-derived content at warn/error — which fire at the enclave's default `info` level (`packages/agent-runtime/src/logger.ts:13`): `read-url-tool.ts:216,227,234,296,302` log `input.url`; `web-search-tool.ts:98,130,139` log the search `query` and Tavily's raw error text; `general-researcher.ts:108` logs substep text ("Searching the web: <query>"). Search queries and URLs are derived from the decrypted prompt — exactly the "what was researched" class the sealed-sources design says must never leave in clear. Contradicts `e2e-encrypted-scratchpads.md:22` ("never logs payloads"); the enclave scrubs its _own_ errors (`session-runner.ts:72-78`) while the tool layer leaks below it.

**Fix:** inject a content-scrubbing logger (or `redactContent` flag) into the shared web tools when built for the enclave; audit every `logger.*` reachable from the enclave-runtime barrel.

### FP-2 (high) — Encrypted threads: Ariadne never sees the anchor message

Plaintext `buildThreadContext` prepends the parent message the thread was opened on — its own comment says "the reply chain is unintelligible without it" (`agents/context-builder.ts:341-371`). The enclave dispatch ships only `findSurrounding` over the thread stream (`enclave-invoke-worker.ts:110`; `request-builder.ts:89-95`), so the first turn in a new encrypted thread has empty history and "what do you think about this?" has zero referent. The system prompt is also built against the root scratchpad with no thread framing (`enclave-invoke-worker.ts:111-113,129`).

**Fix:** include the anchor message's ciphertext (sealed under the same root SSK) as the first history item in the assignment.

### FP-3 (medium) — `@ariadne` mention in a quiet encrypted scratchpad is silently dead

Plaintext mentions invoke Ariadne regardless of companion mode (`mention-invoke-outbox-handler.ts:138-163`). For E2E the mention handler short-circuits (mentions ride in ciphertext, `:113-116`) and the enclave dispatch fires only with companion mode ON (`enclave-dispatch-handler.ts:104-125`). Quiet encrypted scratchpads are a supported state, and the composer's @-mention suggestion is not e2e-gated — the user types `@ariadne`, it renders as a mention, nothing ever happens.

**Fix:** let the client set a clear, non-secret "invoke companion" flag on the sealed send (the client sees the plaintext mention), honored by dispatch even in quiet mode — or suppress persona mentions in the E2E composer with an explanation.

### FP-4 (medium) — Enclave turns invisible to AI usage/cost accounting; data reported then discarded

The enclave sums non-secret token usage (`enclave-ai.ts:40-41`) and ships it on `/complete`; the schema parses it (`session-handlers.ts:60-64`) but the handler reads only `messageIds` (`:448`) — `usage` and `model` are dropped. Plaintext turns are cost-attributed via `ai_usage_records`. Token counts aren't secret; nothing in the trust model forbids recording them.

**Fix:** write an `ai_usage_records` row in the complete handler from `usage` + `model`.

### FP-5 (medium) — History fidelity: bare role/content vs timestamps, authorship, msg-ids, reactions, quote expansion, rolling summary

Plaintext history is annotated (`[msg:… author:…] (14:30)`, date boundaries, attachment captions, reactions — `companion/prompt/message-format.ts:7-27`), quote/shares expanded (`companion/context.ts:177-280`), with a rolling summary for older context. Enclave history is `{ role, content }` only (`run-turn.ts:137-149`) over a 30-message window — "what did I write yesterday?" is unanswerable, and sealed replies can never carry quote pointers. Timestamps/authors are clear metadata the backend already has.

**Fix:** ship per-message `createdAt`/author metadata on the assignment and format with the shared temporal formatter in-enclave; consider an in-enclave rolling summary.

### FP-6 (medium) — Office documents (xlsx/docx) readable by plaintext Ariadne are dead weight in the enclave

Server extraction pipelines (excel/word/pdf/image-caption) feed plaintext context; the enclave handles images, PDFs, and UTF-8 text but degrades anything else to "binary format I can't read" (`run-turn.ts:322-336`) while the backend still ships the bytes at full cost. Server extraction is off by design; in-enclave parsing is not forbidden.

**Fix:** bundle a minimal xlsx/docx extractor into the enclave, or document the boundary (the feature doc currently claims broad "Ariadne reads them too").

### FP-7 (medium) — GitHub/Linear tools missing from encrypted Ariadne beyond the stated exceptions

Plaintext scratchpad Ariadne gets 15 GitHub + 4 Linear read tools, also inside `general_research` (`built-in-agents.ts:73-91`; `general-researcher/config.ts:49-77`). The enclave is web-only. These are third-party reads, not workspace reads; the enclave could call them directly with short-lived tokens minted into the assignment (same egress pattern as Tavily).

**Fix:** ship scoped tokens on the assignment and run the same tool defs in-enclave, or add GitHub/Linear to the documented intentional-off list.

### FP-8 (low) — `web_search` recency grounding built but unwired

`run-turn.ts:102-106` and `tools.ts:72` accept `currentTime`/`timezone`, but `session-runner.ts:65` constructs `tools: { tavilyApiKey }` only — never populated. "Latest/news" searches lose date anchoring.

**Fix:** pass `currentTime` (and owner timezone from the assignment) through `session-runner.ts`.

### FP-9 (low) — Encrypted Ariadne cannot react to messages

`react_to_message` is in the plaintext tool list; absent from the enclave's. Reactions are clear metadata (users can react on E2E messages; emoji stats handler merely skips).

**Fix:** add a clear-metadata `react` session callback + tool, or list as intentional-off.

### FP-10 (low) — Inline "Ariadne is working…" card always reports 0 messages for enclave turns

`emitInlineProgress` hardcodes `messageCount: 0` (`session-handlers.ts:147`) even after interim replies; plaintext increments.

**Fix:** count `message_sent` steps in the same handler.

### FP-11 (low) — Enclave CONTEXT trace step omits the "Recent context" message list

Plaintext `context_received` carries trigger + up to 4 preceding messages with a dedicated renderer section; the enclave seals exactly one message (`trace-observer.ts:184-209`) despite having decrypted history in hand.

**Fix:** include the last few history messages (capped, mirroring plaintext) in the sealed context payload.

### FP-12 (low) — Quiet encrypted scratchpads never auto-title; titled ones only after Ariadne's first reply

Plaintext naming fires on any message in an unnamed scratchpad. Enclave titling requires companion ON + successful reply (`enclave-invoke-worker.ts:170`; `run-turn.ts:261-276`). The naming handler's comment "The client picks a name locally instead" (`naming-outbox-handler.ts:120-121`) describes code that doesn't exist.

**Fix:** client-side title generation + seal on first send for quiet E2E scratchpads, or correct the comment/doc.

### Verified parity (positive confirmations)

1. Same `AgentRuntime` loop and full `buildSystemPrompt` (temporal grounding, response style, custom instructions, owner timezone) — `enclave-system-prompt.ts:31-69`.
2. Model config parity (same persona model/temperature/maxTokens on the assignment); zero-retention OpenRouter (`provider.data_collection: "deny"`, `apps/enclave/src/llm.ts:71-79`).

4. Multi-message turns / interim replies streamed as emitted, deduped by enclave-minted id.
5. Stop-research routes by ownership to the per-session `AbortController`; partial findings + partial badge work.
6. Per-stream tool policy enforced end-to-end (`request-builder.ts:112-115`; `tools.ts:62`).
7. Attachment reading: trigger eager multimodal, history on-demand via `load_attachment`, graceful unavailable notes.
8. Memory exclusion holds at both ends: server short-circuits on memo accumulator (`memos/accumulator-outbox-handler.ts:142`), memo embedding (`:103`), boundary extraction (`conversations/boundary-extraction-outbox-handler.ts:108`), naming (`:122`), companion (`:116`), mention (`:113`), activity (`:142`); enclave builds nothing memory-shaped, emits no Langfuse/OTEL, scrubs OpenRouter errors and session failures, redacts HTTP access logs. The one crack is FP-1.
9. Message actions on encrypted replies: copy-as-markdown/plain off the decrypted payload; Edit hidden; Share behind explicit decrypt confirmation. Neither path has regenerate — parity by absence.
10. Companion/Quiet toggle honest on E2E with live thread inheritance.
