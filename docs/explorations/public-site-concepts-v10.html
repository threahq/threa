02 How memory works · capture · hold · return

Conversation becomes memory.

Threa reads the conversation, lifts the segment that carries a decision, and holds it as a memo — paraphrased and sourced — so it can come back when the topic does.

What's shown here is the real mechanic, not a metaphor. Threa extracts decision-bearing segments from a conversation (boundary extraction in the backend), holds each as a memo that points back to its source messages, and surfaces it when a related question returns. There's no persistent graph of "related memos" on day one — relations live implicitly through the source-message links and Ariadne's retrieval. 03 Open source · fork · host · audit

Open source. Your knowledge stays yours.

Threa is built in the open. Read the code, fork it, run it on your own infra. The memory you build belongs to you — not to a vendor that can change its terms.

Public source

Frontend, backend, control-plane, infra. All of it on GitHub — including the wrong turns and the design explorations.

Self-hostable

Run it on your own hardware. The same stack we deploy is the stack you'd run — same code, same migrations, same defaults.

Built in the open

Roadmap, design notes, decisions, retros — public. Open source the process, not just the artifact.

04 Bring your own agent · export · open · yours

Your data. Your agent. Yours to take.

Threa ships Ariadne — fast, contextual, useful from day one. But your real leverage is the agent you already pay for. Bring your Claude, your Cursor, your custom stack. Threa's job is to make sure the memory it builds for you is something you can pick up and carry — clean enough to feed straight to whatever agent you want.

Data, exportable

Memos as JSON. Messages as markdown. Streams as transcripts. Export from the UI or the API — no CSV-purgatory, no support tickets, no proprietary lock-in.

Agent-agnostic

An open read API over your workspace. Point whatever agent you trust at it — they see the same memory Ariadne does, with the same source links and timestamps.

Yours, not ours

We don't train on your data. We don't sell it. We don't borrow it. Your workspace is private to you and the agents you wire up — that's the whole point.

The built-in agent is the starter motor. Yours is the engine.

Why both? The built-in agent is for zero-config, day-one usefulness — most teams want something working before they wire up an external stack. The open data plane is for day-two, when your own agent, your own prompts, and your own tools start to out-leverage anything we could ship inside the walled garden. We don't pick one. We ship both.
