Brief · home page · five directions

Five ways the threa.io home page could feel.

The home page leads with the what and why of Threa, with a quiet invite to the manually-vetted waitlist. Five aesthetic worlds below — each its own typography, mood, and motion — anchored to the same gold-on-cream token system. Pick one to push forward; we'll adapt About and Developer from it.

Source-of-truth tokens

All five concepts inherit the canvas, primary, and rule tokens from apps/frontend/src/index.css. The vesica-and-thread mark and the breathing Ariadne icon both render from the same SVG paths the product uses.

What's different per concept

Each concept commits to one display face and one mood. Body stays on Space Grotesk so the family between site and product is unbroken; metadata stays on JetBrains Mono so the "tinker-friendly" feel reads without leaning on terminal clichés.

What's shared across all five

· Gold (38 65% 50%) reserved for the brand thread.
· One CTA: request access to the early circle.
· Same headline beat: chat that remembers.
· No terminal frames, no green-on-black, no "hackerzzz".

What it is

A chat with a memory of its own — built for one person first, then a team.

i.

Scratchpads first

You start with a scratchpad, not a channel. Talk to yourself, think out loud, paste the half-formed thing. Threa listens, files what it learns, and leaves the rest alone.

ii.

Memory, by design

Decisions, definitions, agreements — extracted from your conversations and held in a structure you can ask anything of. You wrote the note once. Now ask Threa for it.

iii.

Ariadne, by your side

A small companion that holds the thread when the conversation tangles — summarising, reminding, asking the question you didn't quite finish. Quiet when you don't need her.

The opposite of "Slack, where critical information comes to die."

Entry 03 · specimen page

Why we keep saying "chat that remembers".

Most team chat tools optimise for speed of message. Threa optimises for survival of meaning. The conversations look familiar. What's different is that a week later, a month later, the decisions are still askable — in plain language, with citations back to where you said them.

The first version is built around one person. The architecture is built for a team. Solo-first isn't a marketing line; it's how the product earns its second user.

Picking one to push forward.

Each direction is internally coherent, so the right pick is the one whose tone you want to live with for a year. Below — quick prompts to narrow it down, plus the decisions we'll need to make once a direction is chosen.

Questions for Kris

  • Which mood do you want a first-time visitor to leave with?
  • Should the home page show Threa (mock product) or describe it (manifesto)?
  • Do you want the site to feel like the product family — or a deliberate counterpoint to it?
  • Light, dark, or a per-page choice (e.g. dark Developer page)?
  • Any direction that's an instant "absolutely not"? That's signal too.

What we'll do once a direction is picked

  • Adapt About from the chosen direction's typography and rhythm.
  • Design Developer — API reference, examples, recipes — without losing the brand voice.
  • Decide the waitlist form's mechanics (email + open-ended note vs. structured).
  • Bring the site into a small framework (Astro or Vite) — currently a static doc.
  • Pull the live tokens from apps/frontend/src/index.css so the public site can't drift.
